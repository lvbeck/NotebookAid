# T05-A 原生跨库导入验收

T05 与 T05-A 均待用户验收，不提交 Git，不进入 T06。版本：0.5.0-t05a.2。

## 操作

1. 打开“选择笔记本”，在**目标库**卡片点击“从其他笔记本导入”。若目标不是当前库，先保存当前编辑并切换目标。
2. 选择旧库根目录（包含 library.json）。请先在其他 NotebookAid 实例中关闭来源库；可在同一个实例先切换到目标库，再选择旧库路径。
3. 预览来源、目标、库格式版本，新增笔记／历史修订／文件夹／标签数、重复跳过数、ID 冲突数。取消只取消导入，不写来源、不升级目标。
4. 确认“备份目标库并导入”。目标升级至库格式 3；来源保持原版本与文件内容。成功显示消息和备份路径，成功消息自动已读。
5. 在全部笔记中打开导入内容，核对标题、正文、原格式、链接、图片引用、文件夹、标签和置顶。原生正文按原样复制，不经过富文本或交换格式转换。
6. 再次导入相同库：已导入且未变化的笔记跳过。来源笔记有更新时另建副本，目标已有笔记不覆盖；同标题本身不是重复判断依据。
7. 继续按 [T05 测试](t05-testing.md) 验收其他组织、搜索功能。

## 合并与兼容边界

- 支持 NotebookAid 已知库格式 1、2、3，以及 Markdown／HTML／TXT 原生正文。库格式版本与应用版本不同。
- 导入每篇笔记 head 指向的完整历史链，保留时间、内容版本、置顶和删除状态。T07 之前没有历史／回收站界面；可核对 revisions 文件及 metadata。未提交孤立修订和旧事务日志不作为笔记导入。
- 相同文件夹路径（名称忽略大小写、NFKC 规范化及首尾空白）合并；同名同色标签合并，同名异色标签使用 `(2)` 等后缀。同 ID 冲突生成新 ID，并重映射所有历史中的文件夹／标签引用。
- 不复制来源的本机最近使用、应用设置、索引或注册列表。已删除笔记保留删除状态，不出现在普通列表。
- 附件存储和加密尚未实现，遇到这些结构明确拒绝整次导入；图片内嵌数据和地址保留，但不下载外部图片、不搬运相对路径指向的库外文件。
- 拒绝未知较新库格式、损坏历史／哈希、目录联接、同一库 ID、自身或父子目录互导。来源缺少已有 writer 锁数据库时不擅自补建，拒绝导入。
- 预览后来源或目标有修改，确认会报 VERSION_CONFLICT，请重新预览。核心限制：单正文 2 MiB、全部可达修订 10,000 条／256 MiB、文件夹与标签管理各 500、16 层；超限不会部分导入。当前同步导入期间界面可能短暂等待，大库分批导入尚未实现。

## 备份与回退

写入前在目标库**同级**创建 `<目标目录名>.import-backups/<事务 UUID>/`，复制完整目标库并逐文件校验；只排除进程 writer 锁及其侧文件。此备份独立于程序 ZIP，不属于测试便携目录备份。

格式 3 增加 imports.json 导入收据和导入事务恢复约定。旧版程序无法读取格式 3；不要手改版本号。写入失败自动回滚新增笔记、组织和收据，保留备份；进程中断后，由本版本下次打开目标库恢复。极小的版本切换中断窗口可能只留下格式 3 标记，无笔记变化。

需人工回退时：正常退出 NotebookAid，保留现有目标现场，将显示的备份完整复制到一个新的空目录，再通过重新定位目标库记录指向此副本。不要同时注册两个相同 libraryId 的库。使用旧程序时配合旧程序 ZIP 和升级前库副本。回退将不包含备份之后的新增编辑；请先保留当前库，勿直接覆盖。来源库始终保留，可再次导入。
