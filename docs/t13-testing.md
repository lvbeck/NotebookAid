# T13 Tasks ICS 导入验收

版本：0.13.0-t13.3。T12 已验收并提交本地 main（af9fcf0），未推送。T13 等待用户验收，不启动 T14。

## 操作

1. 在 Thunderbird 日历／Tasks 中将任务导出为 `.ics` 文件。
2. 在 NotebookAid 打开目标笔记本，点击侧边栏“导入笔记”，选择“从 Tasks 导入 ICS”。先显示统一 CDK 对话框，不自动打开文件选择器。目标文件夹默认“未分类”，可选择所有顶层及子文件夹（完整路径显示）。点击“选择 ICS 文件”才打开 Windows 原生文件选择器；选择来源文件后显示预览，尚未写入笔记。
3. 检查每条任务的标题、说明、状态、优先级、完成比例和日期，可展开字段详情。有效条目默认选中；已导入条目只跳过，无效条目禁用并显示具体原因。
4. “确认导入”先创建完整备份，再导入所选任务。备份阶段显示不定进度条，处理阶段显示实际已处理条数和百分比。报告显示导入、跳过、失败数量和备份路径。存在部分写入失败时，成功条目保留，查看报告后重新预览相同文件重试；不要据此反复导入修改后的文件。
5. 导入得到所选文件夹内的普通 TXT 笔记，不自动加密、关联 NotebookAid 标签或创建提醒。需要加密时使用既有安全功能。原 `.ics` 文件和 Thunderbird 任务均不修改。正文仅保存 DESCRIPTION；来源 UID、状态、完成比例及日期等保存为独立只读字段，在正文下方“Tasks 来源信息”中查看，可选中文字复制。

## 字段与日期

| ICS 字段 | 保存位置及处理 |
|---|---|
| SUMMARY | 笔记标题；缺省使用 Untitled task 并提示 |
| DESCRIPTION | 正文说明；支持 ICS 文本换行、转义及折行 |
| UID | 只读 taskSource.uid；导入记录仅保留标识的哈希 |
| STATUS、PRIORITY、PERCENT-COMPLETE | 只读来源字段，不转成 NotebookAid 标签 |
| DTSTART、DUE、COMPLETED、CREATED、LAST-MODIFIED | 保留原日期／时间及语义 |
| VALUE=DATE | 保留 YYYY-MM-DD，并标记 DATE；不转换为午夜 UTC |
| 无 TZID／无 Z 的日期时间 | 保留当地浮动时间，标记 FLOATING，不推定电脑时区 |
| Z | 保留 UTC 时间并标记 UTC |
| TZID | 保留原 TZID 和当地时间；不解析成 UTC 时间点，不依赖电脑时区或在线时区库；VTIMEZONE 定义不转存到笔记 |
| RRULE、RDATE、EXDATE | 保留规则文字并提示，不生成无限任务实例 |
| RECURRENCE-ID | 作为 UID 的例外标识，建立独立笔记并提示 |
| DURATION、CATEGORIES、LOCATION、URL、SEQUENCE | 保留只读来源字段；URL 只作为文字，不自动访问 |
| VEVENT 等非 VTODO | 不导入，报告忽略数量 |
| VALARM、附件、未知／扩展字段 | 提示不支持，不执行提醒，不载入外部资源 |

日期和文本格式参照 [RFC 5545](https://www.rfc-editor.org/rfc/rfc5545)。解析使用 [ical.js 2.2.1](https://github.com/kewisch/ical.js)，依赖锁定并保留 MPL-2.0 许可证；未修改该库。

## 验收步骤

- 使用你自己的 Thunderbird 导出样本检查字段与日期；本轮自动化夹具不代替真实导出文件。
- 取消预览不应创建笔记或备份；坏 UTF-8、坏结构、无 UID、重复 UID、非法字段／日期应提供具体报告。
- 导入相同文件两次：第二次只跳过。先修改本地笔记，再导入相同来源，仍不改本地内容。
- 修改来源说明或字段后再导入：预览提示“来源更新，另建副本”，确认后建立独立笔记，原本地修改保留。
- 混合全日、浮动、UTC、TZID、重复模板与例外，检查没有隐式 UTC 换算或重复展开。
- 查看导入前备份，恢复到另一目录后原有笔记应保持；完整备份还保留已有导入记录。
- 预览期间来源或目标改变、锁定／切换笔记本或应用门禁锁定，应拒绝过期确认；重新选择文件才能继续。
- 检查普通 Markdown／HTML／TXT／Delta 文件导入仍可从同一菜单使用。

## 存储、限制及回退

- 独立来源字段需要笔记本架构 10。导入前完整备份先完成，再升级清单；TXT 正文与来源元数据沿用原有修订和加密接口。旧版本无法读取架构 10，回退程序还需恢复升级前备份。
- 笔记本根目录 `tasks-imports.json` 为独立版本 1 导入记录，保存 libraryId、UID／例外标识哈希、字段快照哈希、操作 ID 和目标笔记 ID，不保存说明、任务标题、密码或原文件路径。原子写入，损坏时保留原件并拒绝继续。
- 去重按当前笔记本及 UID／例外标识、映射字段快照判断。DTSTAMP 等非映射字段变化不重复生成。移入回收站保留导入记录；永久清除笔记时清理其对应记录，再次导入同一来源按新增处理。旧版遗留且笔记目录已不存在的记录在预览中忽略，确认并备份后清理。
- 导入记录随完整笔记本备份和恢复保留；原生跨笔记本导入只保留笔记内容，不迁移 ICS 去重记录。在另一个笔记本再次导入 ICS 会重新建立笔记。
- 文件最多 2 MiB、500 个 VTODO，导入记录最多 10,000 条，字段和嵌套深度有界。只接受 UTF-8；不能可靠去重的无 UID 任务不导入。预览仅在内存保存，十分钟后失效；不发送给 AI。
- 导入前备份位于笔记本同级 `<目录名>.tasks-backups`，不自动清理。批次采用逐笔记原子提交；中断可能已有部分条目成功，重新预览同一来源按操作记录重试，不覆盖既有笔记。
- 程序回退可使用保留的 T13.1 ZIP，完全退出后替换程序文件；该旧版本无法读取架构 10，必须将本轮导入前完整备份恢复到另一目录后重新定位，导入记录文件随备份保留。数据回退请将导入前备份恢复到另一目录并重新定位，避免覆盖唯一原件。

未实测用户自己的 Thunderbird ICS 导出、全部自定义时区规则、Win10 和大规模文件；不将模拟／构建验证描述为真实导出验收。

## T13.2 旧版笔记与批量清空验收

- 重选之前导入的同一 ICS：未修改且 UID／来源字段快照和导入记录能精确核对的旧 TXT 条目显示“旧版笔记，分离来源信息”。确认后先备份，保留原笔记 ID、文件夹、标题和历史，将原始 DESCRIPTION 保存为正文，来源字段独立保存；报告增加“已转换”。不新增副本。正文改过、来源已变、更改过嵌入元信息、已删除或无法核对的条目不自动剥离。重新导入来源变更仍另建副本。
- 笔记列表标题右侧垃圾桶入口“批量清空文件夹”，默认选当前文件夹；全部笔记视图默认“未分类”，不能误将全部笔记视图当作全库删除。下拉可选所有完整子路径；默认不含子文件夹。
- 选择目标目录和“包含子文件夹”后检查待处理数量。该范围指未在回收站的笔记，不受搜索、标签、置顶、分页筛选影响。文件夹和其他目录笔记保留。
- 默认“移入回收站”。选择“永久删除”后显示正文／历史／附件会删除的说明，必须勾选确认才可执行。执行前先保存并释放当前编辑会话，创建同级 .folder-backups 完整备份，再逐项处理并展示真实进度及失败报告。
- 永久删除从当前笔记本文件中清除笔记，操作前备份仍保留，可用于恢复；不等同于清除所有备份中的内容。失败或中断可能有部分成功；移入回收站成功但永久删除失败的笔记可到回收站继续处理，勿盲目重复执行。
- 原生窗口关闭、切换笔记本、写入、安全设置、AI 与 addon 操作在批次运行时阻止并发；失去授权或所有者后停止后续项。大量备份／单项文件写入仍可能耗时，备份用不定进度条，不显示虚假百分比。

## T13.3 强制重新导入

移入回收站不会清除来源记录；永久删除会清理对应记录并允许普通重导。重新选择同一 ICS 后，仍存在的已导入条目默认跳过；要另建副本，勾选“强制重新导入”，选择目标文件夹及要重导的条目，再确认导入。无效条目仍不能选择，强制选项默认关闭且更换来源文件后复位。强制模式会先备份，在目标目录创建新 ID 的笔记，不覆盖本地编辑、不恢复或清除回收站旧笔记；已有内容可能产生副本。默认模式只选择可执行条目，全为重复条目时确认按钮禁用。

强制模式首次执行将 tasks-imports.json 升至记录格式 2，保留格式 1 的历史行，为强制副本增加独立操作 ID 和 force 标记。格式 1／2 均可读，操作中断后重试相同文件和目标目录会复用未完成强制操作，避免重复副本。重复完成一次强制导入后，再次明确开启强制模式会再次创建副本。旧 T13.2 程序的 ICS 导入不能读取格式 2；回退须恢复强制操作前备份，笔记本架构保持 10。
