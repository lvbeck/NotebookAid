# T03-B 多笔记库验收

版本：0.3.0-t03b.1。T03-A 已获用户验收批准；本任务仅实现库列表与路径管理，T03-C 分层设置、Windows 右键入口尚未开始。

## 启动与测试

先从托盘明确退出旧版，再运行本版 NotebookAid.exe。第一次运行会导入旧 library-location.json 指向的库，或已有默认库；旧路径文件原样保留，并在导入前保存 library-location.json.t03b-backup。语言、主题、自动保存偏好保持原存储方式，本任务不迁移笔记内容或数据库格式。

1. 点击左侧“选择笔记库”，应进入列表页。每张卡片显示名称、完整路径、最近打开时间、当前库标记和状态。顶部面包屑显示当前库名称。
2. “创建新笔记库”选择空目录（可在目录选择框中新建文件夹），创建后加入列表；“添加已有笔记库”只能选择包含有效 library.json 的库根目录。两者均不自动切库，点击“打开”切换。
3. 使用两个测试库分别建立不同笔记。关闭自动保存后修改笔记，再切库；切回时修改应已保存，另一库内容不受影响。快速重复点击也不应串库。
4. 修改显示名称，重启后名称、路径和上次活动库保留。名称仅属本机显示偏好，不改目录名；消息中心用登记名称显示关联库。
5. 同一路径（含大小写变体）不可重复添加；不同路径存在相同库 ID 时提示可能是副本。不会合并、改写 ID 或自动登记副本。
6. 先切走测试库并退出程序，手动移动该测试库目录。再次启动并打开旧记录应报不可用，原路径不应产生空库。使用“重新定位”选中移动后的库，ID 核对成功后路径更新；选另一个库应拒绝。
7. “从列表移除”先显示确认，取消不改变列表，确认只移除记录。当前库的移除和重新定位按钮禁用；先打开另一个库后操作。移除后可重新添加，原文件仍完整。
8. 上次活动库离线／丢失时，启动进入库列表，不自动切到其他库。可选其他库、恢复连接后打开，或重新定位。旧路径在首次导入时已丢失且无法取得库 ID 的记录，不能安全核对重新定位：恢复原路径后打开，或添加已确认的库再移除旧记录。
9. 库被其他进程占用、目录不可访问、格式不兼容时，列表项保留并说明原因。可点击“刷新状态”重试检查。不要用个人数据人为制造磁盘或权限故障；失败保护已使用隔离测试库验证。

## 存储、兼容与异常

- 注册表位于应用配置目录 `%APPDATA%\NotebookAid-T02\libraries.json`，schemaVersion=1；保存 entry ID、libraryId、显示名称、绝对路径、最近打开时间和上次活动条目。与笔记内容和索引分离。
- 配置先写临时文件、fsync、原子替换；切库先保存草稿，再检查目标身份与锁、持久化配置，成功后才关闭原库。失败时原库与编辑会话保留。损坏／未知版本的注册表保留原件并报告错误，不静默覆盖或恢复默认库。
- 仅第一次全新配置且默认目录不存在时初始化默认库；已登记路径或旧路径配置缺失时绝不自动新建。
- 新建库成功但列表写入失败时，新库文件保留，按“添加已有笔记库”重试，不删除已经创建的文件。
- 添加已有库先验证清单，打开时再获取写锁、检查笔记内容和重建派生索引；“可用”不是逐条笔记完整性检验。异常状态还可能需要刷新后更新；网络盘长时间断线检查不保证即时返回。
- 重新定位只更新记录，不搬移文件；实际数据迁移、备份和加密分别留在后续任务。本版不将任意普通目录当作已有库。
- 新增库管理错误的具体原因显示在库列表；写入消息历史时使用已有兼容错误分类，方便回退到 T03-A。历史仍只保留 100 条，不记录路径或笔记正文；普通成功消息保持已读。

## 回退

明确退出本版后，可运行保留的 0.3.0-t03a.2。旧版忽略 libraries.json，并继续使用原 library-location.json／默认路径，因此回退后可能打开原库而不是 T03-B 最后选择的库。新库文件仍保留，旧版可手动选择有效库；请勿在旧版选择已移动后缺失的路径。恢复运行本版继续读取其库列表。不要删除注册表或备份文件来尝试回退。

测试 XPI 仍为 0.2.4，协议未改动。仅运行桌面测试不需要重新注册桥接；插件启动新版目录时按既有指南重新注册路径。
