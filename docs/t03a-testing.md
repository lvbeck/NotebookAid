# T03-A 消息中心验收

版本：0.3.0-t03a.2。用户已授权 T03-A，历史上限明确为 100 条。T03-B 多库列表和 T03-C 分层设置没有开始。

## 启动与入口

先从托盘明确退出旧版，再运行本版 NotebookAid.exe。笔记本沿用现有配置；本版不迁移笔记内容或修改正文格式。

- 顶部铃铛显示未读数，点击打开右侧“消息中心”。
- 消息卡片默认在应用窗口右下角弹出，包含状态图标、类型、说明、关闭和“查看历史”。
- 左下角“全局设置”增加消息中心选项，可选右下／左下／右上／左上位置。入口改名与按库设置留在 T03-C。
- 所有卡片与历史面板跟随浅色／深色／系统主题。消息类型、按钮等新增文本提供中／英／德资源；完整八语言仍在 T14。

## 手动验收

1. 修改并手动保存测试笔记，确认“成功／保存成功”卡片。关闭卡片后从铃铛进入历史，该记录应仍在且为已读，铃铛未读数不增加。Info、警告、错误默认未读；旧版成功记录也按已读显示。仅打开消息中心不会把全部记录标已读。
2. 点击“技术验证 → 重建索引”，正常库应显示成功；有未处理恢复项／损坏数据时显示警告，保留原有库状态提示，不将部分成功说成完全成功。
3. 成功卡片约 4 秒后关闭，信息 5 秒、警告 8 秒；错误不自动关闭。鼠标停留或键盘焦点在卡片内时暂停倒计时，离开后继续。短时间最多显示 3 张，更多消息仍记录在历史。
4. 在“全局设置”更改弹出位置，再手动保存确认位置。重启后位置应保留。
5. 消息中心支持类型、笔记本／应用、只看未读筛选。单条或全部标已读后铃铛计数同步；删除一条消息、清空历史也同步。清空历史必须先确认，取消不会删除记录。
6. 通过 Tab／Shift+Tab 在消息中心操作，焦点应留在面板内；Esc 关闭后回到入口。关闭消息卡片不抢走正文编辑焦点。实际屏幕阅读器、高 DPI、德语长文案请在自己的环境复核。
7. 开启自动保存并编辑：成功只更新笔记保存状态，不弹成功卡片、不新增成功历史。失败会记录错误。同一库、操作和错误在 10 秒内连续出现时聚合计数；短时间连续设置变更也合并。已手动关闭的重复错误不会连续重弹，仍更新历史未读数。
8. 正常退出再打开，检查消息、已读状态和位置仍保留。历史仅留最近更新的 100 条，超限淘汰最旧记录；不影响笔记历史版本。

## 数据和异常边界

- 新增 `%APPDATA%\NotebookAid-T02\notifications.sqlite`，schemaVersion 由 SQLite user_version=1 标识，仅保存固定消息代码、操作、库 ID、允许的错误码、时间、次数、已读状态和位置。沿用的 T02 目录名属于应用配置，不是笔记内容目录。
- 不记录笔记标题／正文、密码、解密内容、API Key、令牌、HTML 或原始服务响应。当前库通过短 ID 区分；友好库名称随 T03-B 的库注册表接入。
- 数据由主进程受限 IPC 写入。通知历史与可重建的笔记 catalog 索引分离；清空历史不修改笔记。
- 通知历史故障时显示“消息历史暂不可用”，笔记保存继续独立运行，操作结果仍可临时显示；历史失败的消息不保证补录。可点击“重试读取历史”。损坏文件保留，不自动删除重建。
- 自动故障测试仅用项目 output 中的测试库；不需要对个人数据制造磁盘故障。真实中文输入法、Windows 10、断电和大库场景不因本次 UI 测试而视为通过。
- 本任务尚无长时间后台任务；保存和重建使用现有“进行中”状态，完成后写一次结果；未来任务的进度更新机制随该任务接入。

## 回退与下一步

明确退出新版后，可运行保留的 0.3.0-t03a.1（旧版成功历史可能重新计入未读）；也可退回 0.3.0-t03.2。旧版不读取新通知数据库，原主题、语言、自动保存及笔记本路径未迁移，笔记内容不受影响。保留 notifications.sqlite，恢复运行新版时仍可查看历史；无须手动删除文件。

每次打包按独立版本目录交付。测试 XPI 仍为 0.2.4，本任务不变更 Thunderbird 桥接协议。只测试桌面通知时无须重新注册桥接；若用插件启动新版目录，应按 T03 指南调整注册。

完成测试后反馈结果。仅在你明确批准 T03-A 并授权 T03-B 后，才开始笔记本列表任务。
