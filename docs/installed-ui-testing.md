# 安装版通用 UI 回归

本次修正只涉及测试。通用 UI 断言读取实际更新服务状态并核对对应本地化提示；安装版运行器显式要求 `unconfigured`，Windows 便携／开发运行器显式要求 `portable`，不通过放宽文本匹配绕过环境判断。

在 Windows PowerShell、项目根目录运行：

```powershell
node node_modules/typescript/bin/tsc -p tsconfig.desktop.json
node scripts/ui-installed-smoke.cjs
```

默认目标为 `C:\Program Files\NotebookAid\NotebookAid.exe`，也可将实际安装的 EXE 绝对路径作为第一个参数。需要 Node 24、项目依赖及安装版的有效 `installation.json`。当前实际验证目标是所有用户安装的 MSI 0.15.27；未以本次结果声称 NSIS 或 macOS 实机通过。

运行器创建独立 `output/ui-installed/<timestamp>` 合成笔记目录，两次启动真实安装版，依次运行完整通用 UI 和重启检查。通过临时、仅监听 `127.0.0.1` 的主进程调试入口，在应用启动时只替换 `ui-smoke` 测试模块；执行前恢复模块加载器，被测产品逻辑和前端仍从安装版加载。测试所需的期望值字典来自工作区编译结果，本次已核对与安装版逐字节一致。加载完成即关闭调试连接，测试结束正常退出应用。它不覆盖安装目录、安装缓存或已发布资产，不启用更新源，也不访问个人笔记／真实 AI 账户。

成功时生成 `ui-report.json`、`ui-reopen.json`、每轮测试模块路径／摘要证明、截图和 `installed-ui-verification.json`。验证最后一项的主程序、ASAR、安装元数据及测试模块摘要与运行前一致。实体键盘／输入法、屏幕阅读器、真实 Passkey 和打印机不属于该自动化通用 UI 回归。
